# Current Status

## Working

- D&C hull, mesh volume, warp sort, plane cut (16 tests) — all tests pass.
- `kdop_hull_block` / `batch_kdop_hull_mesh` — 5 tests pass. Produces exact hull via extreme-point prefilter + D&C.
- `hausdorff_block` — 5 tests pass. Sampling-based bidirectional Hausdorff distance with linear BVH acceleration.
- `decompose_components_block` / `la_decompose_components` — 5 tests pass. Connected-components decomposition via GPU union-find. Integrated as optional post-processing pass in lookahead_decompose (decompose_components parameter). Inner shells (negative signed volume) are filtered out to prevent non-manifold output from downstream plane_cut. Each output part carries a `cc_id` identifying its source connected component (assigned on first split, inherited by sub-parts); the merge-hulls pass never merges parts with differing `cc_id`, so the final part count stays >= the initial component count. `DC_MAX_OUT`=4096, `LA_MAX_DECOMP`=16384.
- `lookahead_decompose` — cube, L-shape, octocat, convergence, 49160 tests pass. Uses full cost `max(rv, hausdorff)` for stopping criterion, rv-only for tree search. Default depth=2, quick_depth=0, width=60, width2=5.
- `la_find_concave_edges` — concave edge detection kernel. Generates cutting planes from concave mesh edges for first-layer expansion. Exposed via `n_concave_edges` parameter (default 32). Uses `heap_alloc`/`heap_free` from scratch heap for sort+reservoir scratch. 9 tests pass.
- **Merge-hulls postprocess pass** — port of CoACD's greedy hull merging. Optional (`merge_hulls=True` on `lookahead_decompose`, or `--merge-hulls` on the CLI). Six device kernels in `postprocess_merge.cu`: per-pair cost (rv quick-reject → bbox reject → concat + k-DOP hull → rv cost), separate Hausdorff pass on the filtered-concat mesh (coplanar tris dropped along the shared separating plane) against the merged hull, block-level greedy min-cost matching, apply kernel that builds merged mesh + adopts cached hull, and a single-block in-place compaction. All state lives on the GPU. Bench on bunny (5 runs × 20 iters): parts-mean 44.55–45.80 off → 37.20–38.55 on (~16% reduction); time median 302.8–314.1 ms off → 312.0–321.9 ms on (~1–3% overhead).
- `mesh_audit_kernel` / `check_mesh` — GPU topology audit (open edges, non-manifold edges, winding consistency, degenerate tris, OOB indices). Verdict bitmask (MAV_*); drives the CLI `--preprocess auto` gate. Exercised by the preprocess tests (`check_mesh` gates healing assertions).
- **Preprocess (PaMO stage-1 port)** — `ctx.preprocess(verts, tris, resolution)` remeshes arbitrary input into a watertight, manifold, consistently-oriented mesh. Pipeline (all driver-API, no cub in the host path): normalize to padded unit grid → cumesh2sdf UDF rasterize (8-level adaptive layer refinement, probe/fill pairs) → parity sign fill → SDF shift −0.9/R → PDMC Dual Marching Cubes at iso 0 → inverse map to world space. Verified **bit-identical face counts** vs pamo R=256 references (`tests/data/vhacd_data_obj` → `remesh_R256`) on DRAGON_F/Hand1/Teapot/block/camel/casting (bunny: 869340 vs 869348). Resolution guide: 64 ≈ CoACD CPU default (prep_resolution=50), 128 balanced, 256 = pamo default. Output is intentionally dilated by ≈0.9/R·margin per side (same as pamo's `-0.9/R` shift and CoACD's `level_set=0.55`) — thickens thin walls so decomposition sees a solid. Heals openings up to ≈ band (3 voxels); large missing faces are not recovered (upstream behavior). 10 tests pass.

## Not Yet Implemented

- `__cuda_array_interface__` support for GPU tensor input
- **Ternary search refinement** for lookahead cut selection: CoACD refines the MCTS-selected cut position via ternary search (`TernaryMCTS`, up to 10 iterations, epsilon=0.0001) to find the optimal cut within ±interval of the grid point. Our implementation uses only the fixed grid (width/3 cuts per axis). Adding refinement would let the algorithm find exact structural corners (e.g. the L-shape junction) instead of relying on the nearest grid point.
- **Centroid-based mesh volume**: `mesh_volume_warp` computes volume via divergence theorem anchored at vertex 0 (per-mesh), which eliminated the e3-sign-flip / catastrophic-cancellation issue seen when anchoring at the world origin. For non-watertight meshes (open boundary edges from plane_cut ear-clipping giving up), volume is still implicitly closed to the anchor point; error scales with local extent rather than world coordinate. Anchoring at the mesh centroid instead would shrink the implicit closing triangles further for meshes with many holes. Low priority — the main convergence issue is rv-only tree search, not volume accuracy.
